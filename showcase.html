HTTP Range 206 切片中继

⚙️ 核心运作机制：HTTP Range 206 随机寻址

  • RFC 7233 字节区间规范：移动端现代播放器（如 iOS WebKit AVPlayer）点播媒体文件时，通过发送带 `Range: bytes=START-END` 标头的嗅探请求，按需获取音视频容器头部（Moov Box）与切片帧。
  • 边缘流式切片中继 (`/api/video.js`)：Cloudflare 边缘函数拦截客户端请求，解析客户端请求的字节偏移量，向上游动态抓取精确字节流，返回标准的 `HTTP 206 Partial Content` 状态，并注入 `Content-Range: bytes START-END/TOTAL`。
  • 秒级拖拽与全屏硬解：浏览器根据注入的标准标头获知全局总长度，使得移动端与桌面端均可对视频进度条任意 Seek 拖拽、分段预加载缓冲并触发硬件加速解码。

🌐 系统拓扑策略：边缘无损流式管道

  • 全双工流式 Pipe 穿透 (`/api/upload-asset.js`)：移动端直传文件时，客户端直连就近的 Cloudflare 边缘节点，边缘利用 `TransformStream` 管道将二进制 Chunk 实时中继灌入 GitHub Releases 资产库。
  • 零内存溢出风险：流式管道在内存中仅保留毫秒级 Buffer Chunk 滚动透传，边缘无须磁盘暂存与落盘操作，既保障了零服务器存储成本，又实现了超大文件的快速无损分块灌入。
  • 动态 WebP 智能降级：针对相册静态图片资源，边缘网关自适应识别客户端 `Accept` 标头，优先交付压缩比极高的现代化图片格式。

D1 边缘 SQL + IndexedDB 离线事务

⚙️ 核心运作机制：边缘 D1 分布式 SQL 检索

  • 结构化关系型持久化：全站 11,160 核心词汇完整沉淀于 Cloudflare D1 分布式 SQL 数据库中，包含音标、释义、例句、频级（CET4/CET6/GRE/IELTS）以及三级派生词结构。
  • 归一化小写词头索引 (`head_lower`)：在数据库层面预先建立小写归一化前缀索引，检索 API 采用参数化 SQL 结合 `LIMIT / OFFSET` 游标查询，单次边缘查询时间控制在 10ms 级别。
  • 派生词关联三级网络图谱：后端维护词根与词缀衍生派生词关联，单次请求即可向下级展平词族谱系，实现系统化记忆扩展。

🌐 系统拓扑策略：浏览器 IndexedDB 离线双向预热

  • 异步分片事务缓存：首屏由 D1 按需交付前 60 个高频词条以达成极速可交互；后台空闲线程（Web Worker / Idle Callback）异步分批将词库载入浏览器原生 IndexedDB。
  • 本地前缀树零延迟匹配：在 IndexedDB 的 `head_lower` 索引上构建前端前缀匹配游标。用户键盘键入时，直接在本地内存检索，无需任何网络 I/O。
  • 0 网络依赖与纯离线可用：即使用户处于地铁、地下室或飞行模式等断网环境，词库系统依然支持即输即出、毫秒级响应，彻底消除网络波动造成的打字迟滞。

资源网盘全球分发展厅 (pan.html)

短别名路由解耦 · 全球 Anycast 边缘代理网关 · RFC 6266 标头透传与多线程并发中继

CDN 边缘网关中继

⚙️ 核心运作机制：短别名安全寻址与重定向解密

  • 路由与实体解耦：前端界面采用短别名安全路由（如 `/api/download?file=cmfa`、`clashverge`），向外部屏蔽了真实的远端存储路径与上游拓扑结构。
  • 上游 302 自动跟踪解析：边缘网关接收请求后，自动向 GitHub Releases 核心资产库发起 HEAD / GET 握手，跟随 HTTP 302 重定向获取时效性直链地址（Amazon S3 / Fastly CDN）。
  • 全球骨干流式透传：依托 Cloudflare 与国际骨干网络的高速直连，以流式通道穿透回国，保障客户端连接的稳定性与低丢包率。

🌐 系统拓扑策略：RFC 6266 标头保真与多线程切片

  • RFC 6266 附件标头重塑：边缘网关重写并注入 `Content-Disposition: attachment; filename="xxx"; filename*=UTF-8''xxx` 标头，保证各类浏览器与下载工具准确识别原始文件名与 MIME 类型。
  • 多线程分块并发协议：全量透传 `Accept-Ranges: bytes` 与 `Content-Length`，允许 IDM、迅雷、Aria2 等下载器将大文件切分为 8~32 个并行 TCP 线程同时拉取。
  • 无损断点续传支持：网络意外波动时，下载器可基于字节范围断点继续拉取，无需重新全量下载，保障大文件下载体验。

反向信标 + 容灾自愈中继

⚙️ 核心运作机制：反向信标总线与跨 NAT 穿透

  • 反向长轮询架构（Inverted Beacon Bus）：针对家庭宽带无公网 IPv4 且位于运营商级 NAT 之后的环境，由受控电脑运行静默守护进程（`clash_daemon.pyw`），主动向云端 D1 数据库发起周期性握手。
  • 无状态中继与信箱拓扑：外部控制指令（如节点切换、分组选择、延迟测试）以消息实体暂存于云端信箱，受控端每 2 秒拉取指令在本地执行并回传执行结果，彻底免除路由器端口映射。
  • 滑动容差心跳监测：云端以 75 秒滑动时间戳窗口精确判定被控主机在线状态，超时自动标识离线，提供毫秒级感知的状态呈现。

🌐 系统拓扑策略：方案 B 私人中继与多域探活

  • 客户端指纹协议协商：方案 B 私人固定中继（`/api/sub.js`）拉取规则时，自动注入客户端合规特征标头（`User-Agent: ClashMeta; Clash.meta`），通过权威白名单协议直连上游。
  • 多域名备选池探活自愈：云端维护多节点域名池（`dash.xxx`、`sub.xxx`、`api.xxx`），采用并发竞速探活策略，主力域名受阻时边缘毫秒级无感漂移至备选健康节点。
  • Subscription-Userinfo 权威计费透传：中继网关自动嗅探并向下游透传权威流量标头（包含 `upload`、`download`、`total`、`expire` 字节数据），客户端原生展现流量进度条与套餐剩余。

沙县外卖记账与容灾厅 (takeout.html)

离线优先轻量本地事务 · Cloudflare KV 全球分布式双向异步对齐 · 时间戳乐观并发锁

KV 分布式存储 + 乐观并发锁

⚙️ 核心运作机制：离线优先本地状态机

  • 本地零延迟事务：点餐记账、价格核算与历史记录均由浏览器本地存储（LocalStorage）在 1ms 内完成读写，界面交互零卡顿，不依赖即时网络连接。
  • 自增版本与时钟戳审计：每次数据变更均封装为原子事件，携带精确毫秒级时间戳（`updatedAt`）与数据校验指纹，形成不可逆的本地变更版本链。
  • 离线待传队列机制：在离线或弱网状态下，未同步的修改自动压入本地待传队列，网络恢复后触发自动后台静默重传。

🌐 系统拓扑策略：Cloudflare KV 全球分布式对齐

  • 全球边缘键值持久化 (`TAKEOUT_KV`)：网络畅通时，数据通过 `/api/takeout` 异步推送到 Cloudflare 全球低延迟分布式 KV 存储，实现云端原子化沉淀。
  • 时间戳乐观并发锁（Optimistic Locking）：云端与多端设备采用基于时间戳的冲突消解策略。若多台设备同时修改，系统以最新时间戳版本为权威基准完成增量合并，防止数据覆写。
  • 跨设备无缝漫游与凭证隔离：更换新手机或电脑后，输入访问凭证即可秒级拉取云端全量数据，实现跨端数据漫游与私密数据的严密隔离。
